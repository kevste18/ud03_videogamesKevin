# videojuegosKevin — Catálogo de videojuegos con BD relacional

Aplicación de consola en **Kotlin** para gestionar un catálogo de videojuegos, jugadores y sus listas de juegos. Usa **JDBC** con el patrón **DAO** contra una base de datos **PostgreSQL** que corre en **Docker**.

Proyecto final de la UD3 de Acceso a Datos (2º DAM).

## Estructura de la base de datos

Cuatro tablas relacionadas mediante claves primarias (PK) y claves foráneas (FK):

| Tabla | Columnas | Relaciones |
|---|---|---|
| `videogames` | `id` (PK), `title`, `genre`, `release_date`, `rating` | — |
| `players` | `id_player` (PK), `username` | — |
| `lists` | `id_list` (PK), `name`, `id_player` | `id_player` → `players` (FK, `ON DELETE CASCADE`) |
| `videogames_lists` | `id_list`, `id_videogame`, `date_added` | PK compuesta (`id_list`, `id_videogame`); `id_list` → `lists` y `id_videogame` → `videogames` (FK, `ON DELETE CASCADE`) |

- Un **jugador** puede tener varias **listas**, y cada lista pertenece a un solo jugador (1:N).
- Una **lista** puede contener varios **videojuegos**, y un videojuego puede estar en varias listas (N:M, resuelta con la tabla intermedia `videogames_lists`).

El script completo (`CREATE TABLE` + `INSERT` con los datos de prueba) está en:

```
src/data/videogames.sql
```

Datos de prueba: 5 videojuegos, 3 jugadores y 3 listas, cada una de un jugador distinto.

## Instrucciones de ejecución

### Requisitos
- JDK 24 (configurado en Gradle con `jvmToolchain(24)`)
- Docker Desktop
- IntelliJ IDEA (recomendado)

### 1. Levantar PostgreSQL en Docker

```
docker run --name videojuegos-db -e POSTGRES_USER=kevin -e POSTGRES_PASSWORD=<password> -e POSTGRES_DB=videogames -p 5433:5432 -d postgres:17
```

Se usa el puerto **5433** del ordenador para no chocar con un PostgreSQL instalado localmente en el 5432. El usuario y la contraseña deben coincidir con los de `DBConnection.kt`.

### 2. Crear las tablas y los datos

Ejecutar `src/data/videogames.sql` contra la base de datos `videogames` (desde la consola SQL de IntelliJ o con `psql`). El script empieza con `DROP TABLE IF EXISTS ...`, así que se puede ejecutar varias veces para dejar la base de datos en su estado inicial.

### 3. Configurar la conexión

En `src/main/kotlin/db/DBConnection.kt`:

```kotlin
private const val HOST = "localhost"
private const val PORT = 5433
private const val DATABASE = "videogames"
private const val USER = "kevin"
private const val PASSWORD = "<password>"
```

El driver de PostgreSQL ya está incluido en `build.gradle.kts` (`org.postgresql:postgresql`).

### 4. Ejecutar

Ejecutar la función `main` de `main.kt`. Aparece el menú con tres bloques: videojuegos (1-5), jugadores (6-7) y listas (8-11).

## Decisiones de diseño

- **PostgreSQL en Docker:** PostgreSQL porque ya lo conocía de primero, y Docker para no instalar nada en el sistema y poder recrear la base de datos en segundos.
- **Tabla `players`:** solo `id_player` y `username`, porque es lo mínimo necesario para identificar al dueño de cada lista.
- **Relación con `lists`:** columna `id_player` con FK hacia `players`. Al crear una lista, si el jugador no existe, PostgreSQL rechaza el `INSERT` y el programa muestra un mensaje de error sin cerrarse.
- **`ON DELETE CASCADE`:** al eliminar un jugador se eliminan sus listas, y al eliminar una lista (o un videojuego) se eliminan sus filas de `videogames_lists`. Así se mantiene la integridad referencial sin código extra en Kotlin.
- **PK compuesta en `videogames_lists`:** impide añadir el mismo videojuego dos veces a la misma lista.
- **IDs con `GENERATED BY DEFAULT AS IDENTITY`:** los genera PostgreSQL. Los datos de prueba se insertan sin ID para que el contador interno quede sincronizado.
- **Transacción en `addToList`:** comprueba con un `SELECT` que el videojuego existe e inserta en `videogames_lists` dentro de una única transacción (`autoCommit = false`, `commit` / `rollback`). Si algo falla, no se guarda nada.
- **Migración desde SQLite:** gracias al patrón DAO, para pasar de SQLite a PostgreSQL solo se cambiaron `DBConnection.kt` y la dependencia del driver en `build.gradle.kts`.
- **Nombres en inglés:** todo el proyecto (tablas, clases y funciones) está en inglés por coherencia.
